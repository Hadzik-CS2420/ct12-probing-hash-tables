👨‍💻 Code-Together 12: Probing Hash Tables

🎯 Overview

An in-class code-together activity introducing linear probing (closed hashing / open addressing) — the second collision resolution strategy after CT11's separate chaining. Students build a ProbingHashTable that stores entries directly in a flat array, resolves collisions by scanning forward one slot at a time, and uses tombstone deletion to preserve probe sequences. The activity covers load factor monitoring with a lower threshold (0.75 vs chaining's 1.0) and resizing with rehashing that clears tombstones. The scenario continues the professor's grade book: student names are keys, integer grades are values.

📖 Learning Objectives

By completing this activity, you will be able to:

  • Implement linear probing (closed hashing): collisions resolved by scanning forward to the next open slot in a flat array
  • Explain why probing uses a lower load factor threshold (0.75 vs 1.0) — primary clustering makes probe sequences longer as the table fills
  • Implement tombstone deletion: removed entries are marked DELETED rather than EMPTY so probe sequences for other keys are not broken
  • Explain the three slot states (EMPTY, OCCUPIED, DELETED) and how each affects insert, search, and remove operations
  • Implement resize with tombstone cleanup: only OCCUPIED entries are rehashed, clearing all tombstones for a clean table
  • Compare probing vs chaining trade-offs: cache locality vs clustering sensitivity, flat array vs pointer chains

📝 What You’ll Do

Open each source file and complete the TODO comments. Each TODO tells you what to write, and the DISCUSSION comments explain the “why” behind the code. We’ll work through these together in class.

📚 Teaching Order

Work through the files in the order main.cpp calls them:

1. HashSlot.h — The slot structure

Section What You’ll Learn
SlotStatus enum EMPTY (never used), OCCUPIED (live entry), DELETED (tombstone)
HashSlot struct key, value, status fields with default constructor setting EMPTY

2. ProbingHashTable.h — Class declaration

Section What You’ll Learn
HashSlot* vs ChainNode\*\* flat array of structs vs array of linked list pointers
MAX_LOAD_FACTOR = 0.75 lower threshold than chaining's 1.0 due to clustering
Same interface insert, search, remove, hash, load_factor, resize, print

3. ProbingHashTable.cpp — Linear probing implementation (7 TODOs)

Section What You’ll Learn
Constructor allocate HashSlot array; default constructor sets every slot to EMPTY
Destructor simple delete[] table_ (no chains to walk, contrast with chaining)
hash() same multiply-and-add algorithm as CT11; hash function doesn't care about collision strategy
insert() hash the key; resize BEFORE inserting if load factor would exceed 0.75; probe forward with (index + 1) % capacity_ until finding EMPTY, DELETED, or matching key
search() hash the key; probe forward: OCCUPIED + match = found, DELETED = keep probing, EMPTY = not found
remove() find the key; set status to DELETED (tombstone); explain why EMPTY would break probe chains
load_factor() same formula, lower threshold; discuss clustering impact at high load factors
resize() save old array; allocate new prime-sized array; rehash only OCCUPIED entries (tombstones cleared)
print() display each slot: entry, [empty], or [deleted]

4. main.cpp — Professor's Grade Book (walkthrough)

Section What You’ll Learn
Insert students add 5 students with grades into the probing table
Print display the slot layout; notice primary clustering (consecutive occupied slots)
Search look up Charlie (found) and Frank (not found — hits EMPTY)
Update update Bob's grade via insert with existing key
Remove remove Diana; slot becomes [deleted] tombstone
Search past tombstone search for Eve probes past Diana's tombstone
Resize insert Frank and Grace; triggers resize at 0.75 threshold; tombstones cleared
Final print clean table after resize: no tombstones, lower load factor, new positions

🔧 Troubleshooting

CMake does not configure automatically

  1. Check the bottom-left corner of VS Code reads Dev Container. If it does not, press Ctrl+Shift+P and run Dev Containers: Reopen in Container
  2. Make sure Docker Desktop is running, then reopen the folder
  3. Delete the build/ folder and run cmake -B build again
  4. Verify that CMakeLists.txt is in the root of your cloned repository

Tests fail to build

  • Google Test is fetched automatically via CMake’s FetchContent — make sure you have an internet connection during the first build
  • Do not modify header files in the include/ folder

Running the Program

  1. In the container terminal, run ./build/ct11-probing-hash-table
  2. Or press Ctrl+Shift+P and run CMake: Run Without Debugging
  3. You should see output from each section as you complete the TODOs
Tip: Look for the // ! DISCUSSION: comments in each file — these explain the “why” behind each concept. The // ? SEE DIAGRAM: comments point you to visual aids in the images/ folder.
